# Firebase Client Email Quoting Bug

## The Rule
`FIREBASE_CLIENT_EMAIL` must be stored as a bare email string with NO surrounding double-quote characters. If quotes are included, every custom token generated by the Admin SDK has a malformed `iss`/`sub` field, which makes the token unverifiable by Firebase Identity Toolkit.

## Why
Firebase Admin SDK's `createCustomToken()` uses the `FIREBASE_CLIENT_EMAIL` value verbatim as the JWT `iss` and `sub` claims. If the value is `"email@..."` (with quote chars), the JWT payload contains `"iss": "\"email@...\""`. Firebase Identity Toolkit tries to fetch the service account's public key using that string as the email — the embedded quotes make it an invalid URL, so the key fetch fails and the token is rejected with `INVALID_CUSTOM_TOKEN`.

## How to Apply
Any time `signInWithCustomToken` fails with `INVALID_CUSTOM_TOKEN` even though the token is a valid 3-segment JWT with correct audience and non-expired `iat`/`exp`, check whether `FIREBASE_CLIENT_EMAIL` starts and ends with a `"` character. If so, re-enter the secret without surrounding quotes.

## Diagnostic Command
```bash
node -e "const e = process.env.FIREBASE_CLIENT_EMAIL || ''; console.log('starts_quote:', e.startsWith('\"'), 'ends_quote:', e.endsWith('\"'), 'len:', e.length)"
```
If both `starts_quote` and `ends_quote` are `true`, the secret is wrong.
